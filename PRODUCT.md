# Product

## Register

product

## Users

Platform engineers reviewing local Kubernetes Gateway API manifests. They compare a proposed manifest against specific Gateway API releases, inspect schema compatibility, and understand resource relationships without sending manifest content to a service.

## Product Purpose

Provide local CRD compatibility inspection and relationship visualization for Gateway API manifests. Success means the active audit release is always clear, version changes preserve the manifest and editor state, schema compatibility remains distinct from graph coverage and controller conformance, and findings are easy to inspect and correct.

## Brand Personality

Calm, precise, compact. The interface should feel like a dependable engineering workbench, not a dashboard or marketing surface.

## Anti-references

Avoid marketing layouts, hero metrics, decorative effects, glassmorphism, gradients, emoji headings, nested cards, oversized introductions, and color used without semantic purpose. Do not present parent-reference coverage as successful attachment, CRD compatibility as Kubernetes admission, or catalogued features as controller support.

## Design Principles

1. Keep the audit target and exact release visible at all times.
2. Preserve user work and editor context while comparing releases.
3. Separate CRD compatibility, relationship preview, and controller-specific support.
4. Keep editor and topology central; disclose release detail progressively.
5. Use familiar, keyboard-operable controls with concise technical copy.

## Accessibility & Inclusion

Target WCAG 2.1 AA contrast. Support complete keyboard operation, visible focus, textual status in addition to color, reduced-motion preferences, responsive layouts without page-level horizontal overflow, and both light and dark themes.
